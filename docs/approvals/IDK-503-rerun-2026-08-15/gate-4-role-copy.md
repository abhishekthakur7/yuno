## Blocking findings

### 1. Hands-on scenario content authorship remains unimplemented (B10, content half)
- What is missing: The 12 approved IDK-009 `idk009-v1-r1` scenario records are not loaded or bound to topics. Every synthesized `HandsOnWork` row is still hardcoded `scenario_status="fixture"`, `scenario_id=None`, `scenario_source="fixture-pending-idk-009"`.
- Owning ticket: IDK-405 (content authorship), separate from IDK-503/B10/B12's schema-shape work, which is closed.
- Evidence of absence: `server/src/yuno/modules/hands_on/service.py:25-46,110-118`; zero matches for any of IDK-009's 12 scenario IDs under `server/src/yuno/modules/hands_on/`; `HandsOnLab.test.tsx:14` still fixtures `status: 'fixture'` and passes.
- What would clear it: Load the IDK-009 registry content, bind topics to approved scenario IDs/role/level/constraints text, set `scenario_status="approved"` and a real `scenario_id` for approved content, and re-inspect against a live `hands_on_work` row (both local databases currently have 0 rows — `server/yuno.db` and `server/.e2e.db` row counts confirmed via read-only query).

### 2. Onboarding silently preselects and can submit "Senior" without an explicit learner choice
- What is missing: A required, unconfirmed initial state for the level selector on first-use setup, and a submission gate that requires the learner to have made an explicit choice.
- Owning ticket: none identified — this was not flagged by IDK-104/IDK-503's first round and has no tracking ticket found in `IMPLEMENTATION_TICKETS.md` for this specific behavior.
- Evidence of absence: `src/selected/core/CorePages.tsx:202` (`useState<GoalCreate['target_level']>('Senior')`), `:242-246` (submits `targetLevel` unconditionally), `:397` (submit button's `disabled` condition never checks whether the level was touched); `ProfileGoalsPages.test.tsx:266-268` comments this in as intended default behavior rather than treating it as a gap.
- What would clear it: Give the Onboarding level control a genuinely unselected/required initial state (e.g., a null/placeholder value that fails validation until explicitly set), gate submission on an explicit choice having been made, and re-inspect against IDK-004 §4's exact "not... silently becoming Senior" language. Also revisit `BundleEditor.createBundle`'s hardcoded `target_level: 'Senior'` recommended-bundle creation for the same pattern.
