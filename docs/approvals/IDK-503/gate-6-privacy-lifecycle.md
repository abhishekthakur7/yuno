Both `server/yuno.db` and `server/.e2e.db` exist as local dev/e2e SQLite files (not production data) but were not opened for this re-inspection since the passing targeted tests already exercise representative fixture data end to end; a full manual field-by-field inspection of a downloaded export package and live rotated log file (as section 10 of the decision requires for the human reviewer) still needs the designated product/privacy owner's own hands-on pass — that is what "pending attestation" below records.
- Re-verification confirmed the tree has moved past the 2026-08-13 review-evidence baseline (`20f0ea4`) with `d57d7e7` (IDK-408/409), `dc5267f` (export activation), `018ecd8` (runner narrowed to Java-only), `13a28a1` (janitor completion signal), and `4198ecd` (SQLite busy_timeout raised to 30s). None of these commits changed any policy 1.0 numeric value, redaction category, or export/delete contract item found in this inspection; `dc5267f` only flips the already-approved activation flag.
- Drift note (§5 of this gate's brief): `018ecd8` performs an irreversible, migration-driven bulk deletion of `language='relational'` runner confirmations/records and their owned rows (per its commit message) as part of narrowing the runner to Java-only under IDK-005/IDK-008. It does not contradict any approved policy value (no size/retention/export/delete/logging table entry governs it), but it is a data-lifecycle event the current policy text does not explicitly cover. Recommend the product/privacy owner note this as an accepted category during attestation rather than treating it as silent scope creep.
